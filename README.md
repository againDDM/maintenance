# Задание

Получив метрики по статусам сервисов в staytus, коллеги их проанализировали. Часть сервисов деплоится с даунтаймом. Это нормально. А то, что даунтайм сервиса не отображается в `staytus` - это проблема. Во всех ранбуках, описывающих такие деплои есть пометка о необходимости выставления статуса. К сожалению несмотря на это очень часто операторы забывают это сделать. Так как все деплои в компании происходят путём запуска `ansible-playbook`, а большинство сервисов деплоится без даунтайма, срабатывает эффект похожести. Вместе с тимлидом и с коллегами мы пришли к выводу, что правильнее будет, если статус будет меняться из плэйбука. Таким образом получится решить проблему, не изменяя для операторов привычный порядок работы.

1. Клонировать [репозиторий с шаблоном](https://github.com/againDDM/maintenance).
2. Задеплоить версию `old` согласно инструкции в README шаблона.
3. Развернуть staytus (можно использовать способ показанный на лекции).
4. Завести в staytus сервис `example-web-app` (предустановленные сервисы лучше удалить).
5. Ознакомиться с [Ansible Developer Guide](https://docs.ansible.com/ansible/latest/dev_guide/index.html)
6. Используя знания, полученные в предудущем пункте, найти решение, которое позволить выставлять статус `maintenance` в `staytus` на заданный сервис в начале плэйбука и возвращать исходный статус по его завершению.
7. Имплементировать решение. Можно использовать репозиторий с шаблоном для отладки.
8. Подготовить документацию по решению. То есть хозяин плэйбука/роли должен иметь возможность по этой документации подготовить рабочую среду и модифицировать их так, что бы на время деплоя выставлялся статус.
9. Попробуйте самостоятельно, действуя по вашей документации, модифицировать плэйбук из шаблона, задеплоить версию `new`.

Для выполнения домашнего задания рекомендуется использовать машину с ubuntu 22 или выше и предустановленным докером на борту. Для пущего удобства стоит настроить беспарольное sudo.
Критерии успешности: проверяющий смог по вашей документации подготовить рабочую среду и модифицировать шаблон таким образом, что бы на время деплоя на staytus`e на заданном сервисе вешался статус maintenance, а по окончанию деплоя возвращался исходный статус приложения.

# deploy app

## подготовка

Создайте виртуальное окружение

```sh
python3.12 -m venv venv
```

Активируйте виртуальное окружение

```sh
. ./venv/bin/activate
```

Установите ansible и другие необходимые для работы python пакеты в виртуальное окружение

```sh
pip install -r requirements.txt
```

## деплой

```sh
ansible-playbook -e "app_version=old" playbooks/deploy.yml
```

Обязательно передать через опцию версию приложения, которую хотим задеплоить.
Если требуется пароль на sudo, то следует добавить ключ `--ask-become-pass` для ввода пароля через консоль.

**НЕ ЗАБЫТЬ** руками выставить статус `maintenance` в staytus перед деплоем и вернуть исходный статус по окончанию деплоя.
